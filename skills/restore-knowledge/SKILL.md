# 还原知识

把当前对话形成的可复用认知资产还原成适合个人知识库长期保存的 Markdown 文档。本技能完全自包含，不调用或依赖其他技能。

除 `description` 和必要技术标识外，所有面向用户的表达使用中文。

## 确定归档范围

默认处理当前对话。用户指定话题、消息范围或材料时，只处理指定范围。无法访问对话原文时，请用户粘贴材料；不要凭印象补写。

把候选内容路由到四类知识资产：

1. 经过验证的事实：数据、规则、客户反馈、官方文档、系统约束以及已经核实的概念或机制；
2. 形成的判断：用户为什么选择甲而不选择乙，包括取舍理由、关键假设和反转条件；
3. 失败案例：人工智能输出或用户判断被事实证明错误、失效或存在重要缺口的案例；
4. 可复用清单：能够迁移到新场景的提问模板、审查清单、验收清单和风险清单。

一段对话不必同时产生四类资产。只输出实际存在且达到归档门槛的类别，不用空标题或泛化内容凑齐。

不归档：

- 缺少理由和适用条件的孤立选择、批准、承诺和优先级；
- 只对当前任务有效的负责人、日期、待办、状态和措辞修改；
- 寒暄、重复内容、未经支持的猜测和为了显得完整而补出的常识；
- 密钥、账号、精确住址、未公开身份信息或其他不必要的敏感信息。

判断可以记录“用户选择了什么”，但必须与理由、替代方案、关键假设和反转条件一起归档。只有用户明确表达或确认的结论才能称为“用户形成的判断”；人工智能提出但用户未确认的建议不能代替它。行动安排只作为理解判断所必需的背景出现，不把知识文档写成决策纪要。

失败必须有可观察结果、可靠反馈或用户明确确认。意见不同、结果暂时不佳或事后猜测都不足以证明谁错了。根因没有证据时标记为待验证假设。

清单必须可在相似新场景执行，条目应能观察是否完成。只使用过一次的流程标记为“草案”；经过多次有效使用或现实验证后，才标记为“已验证”。

## 识别认知增量

逐项检查候选内容：

1. 是否在本次对话中首次出现，或相较此前得到实质澄清、验证或纠正；
2. 是否能在离开当前任务后仍帮助理解、解释或判断；
3. 是否具有足够上下文，使未来读者无需重读对话；
4. 是否能诚实说明来源、证据状态和适用边界。

无法判断用户此前是否已经知道某项内容时，不声称“用户学会了”，只写“本次对话形成或澄清”。内容只是决策、过程或重复时删除。没有真实认知增量时，直接说明“本次对话没有发现值得归档的新增知识”，不要制造条目。

## 处理证据

只保留对话中实际出现或本轮已经核验的来源，不虚构链接、作者、日期或结论。默认不为归档正文另行扩展主题调研；用户明确要求补证据时才进行查证。文末学习资源的定向核验是例外，但不得借此扩写正文知识。

区分：

- 已核验事实；
- 有来源但本轮未核验的主张；
- 基于已知内容的合理推断；
- 尚待验证的假设。

事实具有时效性时注明核验日期或版本。来源与表述不一致时缩小主张，不用强来源包装弱推断。与关键知识无关的链接不保留。

只有已核验内容才能进入“经过验证的事实”。其余内容分别进入判断的假设、失败案例的待确认根因或待验证问题。客户反馈是“某位或某组客户表达了什么”的事实，不自动代表全部市场。系统行为以实际运行结果为准；人工智能先前的回答不能作为自身正确性的证据。

## 生成深入学习资源

每篇有效 Wiki 后补充进一步学习方向和专属学习资源清单。先从对话识别两到四个最值得继续深入的领域，优先覆盖：

- 用户明确表现出兴趣或“原来如此”等认知突破的地方；
- 当前模型中仍薄弱的机制、证据或实践环节；
- 会扩大视野、提供强反例或帮助迁移的相邻领域。

无法观察用户内心感受时，不声称识别了“啊哈时刻”；只能根据其明确表达和对话中的认知缺口推断，并把推断写成学习建议。

通常推荐三到五项关键资源，可以是经典书籍、核心期刊或专题杂志、值得长期追踪的作者或博主、播客、课程、专栏和权威资料库。选择标准：

1. 与当前 Wiki 的具体知识或缺口直接相关；
2. 每项提供不同的独特视角，整体兼顾理论、证据、反例或实践；
3. 优先原作者、出版社、期刊、机构或频道官方页面；
4. 说明资源能补什么、为何适合当前主题，以及建议从哪里开始；
5. 不因用户给出的类别示例而机械凑齐每一种媒介。

工具可用时，对候选资源做窄范围核验：确认资源真实存在、链接可访问、作者或机构匹配；声称博客、播客、专栏仍在更新时，还要核验近期活动。工具不可用时，只推荐有充分把握的资源，标记“本轮未联网核验”，不编造网址或当前活跃状态。可靠资源不足三项时，宁可少列并说明原因，也不要补齐虚构或低相关资源。

涉及用户私人情境时，用抽象主题检索，不把敏感对话原文发送给外部服务。资源推荐不是新的决策结论，也不得改写已经归档的用户判断。

## 生成 LLM Wiki

阅读[知识归档协议](references/wiki-format.md)，按主题边界生成一篇或数篇独立文档。每篇只表达一个内聚主题；多个主题没有共同解释框架时拆开，避免把整段聊天压成一篇流水账。

输出前完成七项检查：

1. 背景模型是否解释“是什么、为什么、何时成立、何时不成立”；
2. 事实、判断、失败和清单是否使用各自正确的证据门槛；
3. 判断是否保留替代方案、理由、假设和反转条件；
4. 失败是否区分观察结果、已证实原因和根因假设；
5. 清单是否可执行、可迁移并标明成熟度；
6. 文档是否能被未来的人工智能或用户独立理解和检索；
7. 学习资源是否真实、互补，并逐项说明独特视角及与当前主题的关联。

没有有效 Wiki 条目时，不生成泛化学习清单，除非用户另行明确要求资源推荐。

默认只输出 Markdown，不声称已经保存。用户明确提供知识库位置并要求写入时，才执行保存；不得覆盖同名文件，除非用户明确授权。
