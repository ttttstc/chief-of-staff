# 还原知识

把当前对话形成的可复用认知还原成适合个人知识库长期保存的 Markdown 文档。本技能完全自包含，不调用或依赖其他技能。

除 `description` 和必要技术标识外，所有面向用户的表达使用中文。

## 确定归档范围

默认处理当前对话。用户指定话题、消息范围或材料时，只处理指定范围。无法访问对话原文时，请用户粘贴材料；不要凭印象补写。

归档的是本次讨论中被新增、澄清或通过调研获得的知识，包括：

- 概念及其边界；
- 因果机制与相互关系；
- 可迁移的方法、模型和判断原则；
- 方案类型、适用条件、代价与失败模式；
- 已核验事实、来源主张及其证据状态；
- 能帮助未来理解主题的重要反例和限制。

不归档：

- 用户最终选择、批准、承诺、优先级和行动安排；
- 只对当前任务有效的过程记录、待办、状态和措辞修改；
- 寒暄、重复内容、未经支持的猜测和为了显得完整而补出的常识；
- 密钥、账号、精确住址、未公开身份信息或其他不必要的敏感信息。

决策中包含可迁移原理时，只提炼原理，不记录“用户选择了什么”。例如保留“何种条件下分阶段方案降低不可逆风险”，删除“本项目决定采用分阶段方案”。

## 识别认知增量

逐项检查候选内容：

1. 是否在本次对话中首次出现，或相较此前得到实质澄清；
2. 是否能在离开当前任务后仍帮助理解、解释或判断；
3. 是否具有足够上下文，使未来读者无需重读对话；
4. 是否能诚实说明来源、证据状态和适用边界。

无法判断用户此前是否已经知道某项内容时，不声称“用户学会了”，只写“本次对话形成或澄清”。内容只是决策、过程或重复时删除。没有真实认知增量时，直接说明“本次对话没有发现值得归档的新增知识”，不要制造条目。

## 处理证据

只保留对话中实际出现或本轮已经核验的来源，不虚构链接、作者、日期或结论。默认不为归档任务另行扩展调研；用户明确要求补证据时才进行查证。

区分：

- 已核验事实；
- 有来源但本轮未核验的主张；
- 基于已知内容的合理推断；
- 尚待验证的假设。

事实具有时效性时注明核验日期或版本。来源与表述不一致时缩小主张，不用强来源包装弱推断。与关键知识无关的链接不保留。

## 生成 LLM Wiki

阅读[知识归档协议](references/wiki-format.md)，按主题边界生成一篇或数篇独立文档。每篇只表达一个内聚主题；多个主题没有共同解释框架时拆开，避免把整段聊天压成一篇流水账。

输出前完成四项检查：

1. 删除任何决策结论后，文档是否仍然成立；
2. 文档是否解释“是什么、为什么、何时成立、何时不成立”；
3. 关键事实是否保留来源和证据状态；
4. 文档是否能被未来的人工智能或用户独立理解和检索。

默认只输出 Markdown，不声称已经保存。用户明确提供知识库位置并要求写入时，才执行保存；不得覆盖同名文件，除非用户明确授权。
